= Configurar failover em um host Linux para NVMe sobre FC no storage E-Series
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Para fornecer um caminho redundante para o storage array, você pode configurar o host para executar o failover.

.Antes de começar
Você deve instalar os pacotes necessários em seu sistema.

* Para hosts Red Hat (RHEL), verifique se os pacotes estão instalados executando `rpm -q device-mapper-multipath`
* Para hosts SLES, verifique se os pacotes estão instalados executando `rpm -q multipath-tools`


 SLES 12 use Device Mapper Multipath (DMMP) for multipathing when using NVMe over Fibre Channel. RHEL 8, RHEL 9, RHEL 10, SLES 15 and SLES 16 use a built-in Native NVMe Failover. Depending on which OS you are running, some additional configuration of multipath is required to get it running properly.


[[enable-device-mapper-multipath-dmmp-for-sles-12]]
== Habilitar o Device Mapper Multipath (DMMP) para SLES 12

Por padrão, o DM-MP está desabilitado no SLES. Conclua as etapas a seguir para ativar os componentes DM-MP no host.

.Passos
. Adicione a entrada do dispositivo NVMe e-Series à seção dispositivos do arquivo /etc/multipath.conf, como mostrado no exemplo a seguir:
+
[listing]
----

devices {
        device {
                vendor "NVME"
                product "NetApp E-Series*"
                path_grouping_policy group_by_prio
                failback immediate
                no_path_retry 30
        }
}
----
. Configure `multipathd` para iniciar na inicialização do sistema.
+
[listing]
----
# systemctl enable multipathd
----
. Inicie `multipathd` se não estiver em execução no momento.
+
[listing]
----
# systemctl start multipathd
----
. Verifique o estado de `multipathd` para se certificar de que está ativo e em execução:
+
[listing]
----
# systemctl status multipathd
----




[[set-up-native-nvme-multipathing-for-rhel-8]]
== Configure o NVMe Multipathing nativo para RHEL 8

.Sobre esta tarefa
O NVMe Multipathing nativo é desativado por padrão no RHEL 8 e deve ser habilitado usando as etapas abaixo.

.Passos
. Regra de `modprobe` configuração para ativar o NVMe Multipathing nativo.
+
[listing]
----
# echo "options nvme_core multipath=y" >> /etc/modprobe.d/50-nvme_core.conf
----
. Remake `initramfs` com novo parâmetro modprobe.
+
[listing]
----
# dracut -f
----
. Reinicie o servidor para ativá-lo com o Native NVMe Multipathing habilitado
+
[listing]
----
# reboot
----
. Verifique se a opção de multipathing NVMe nativo foi ativada depois que o host inicializa o backup.
+
[listing]
----
# cat /sys/module/nvme_core/parameters/multipath
----
+
.. Se o comando output for `N`, então o Native NVMe Multipathing ainda será desativado.
.. Se o comando output for `Y`, então o Native NVMe Multipathing será ativado e todos os dispositivos NVMe que você descobrir o usarão.





NOTE: Para RHEL 9 e SLES 15, o Native NVMe Multipathing está habilitado por padrão e nenhuma configuração adicional é necessária.



[[configure-nvme-io-policy]]
== Configurar política de E/S NVMe

.Sobre esta tarefa
O multipathing nativo do NVMe no Linux pode usar a  `numa` política de E/S padrão. Para configurações NVMe-over-Fabrics do E-Series/EF-Series, a política de E/S recomendada é  `round-robin`, que distribui a E/S uniformemente entre todos os caminhos disponíveis.

.Passos
. Verifique a política atual de E/S NVMe:
+
[listing]
----
# cat /sys/module/nvme_core/parameters/iopolicy
numa
----
. Defina a  `round-robin`política de E/S usando um dos seguintes métodos:
+
** *Persistente (recomendado)* — Crie um arquivo de regras udev:
+
.<code>/etc/udev/rules.d/71-nvme-io-policy.rules</code>
[listing]
----
ACTION=="add|change", SUBSYSTEM=="nvme-subsystem", ATTR{iopolicy}="round-robin"
----
+
Em seguida, recarregue e aplique as regras:

+
[listing]
----
udevadm control --reload
udevadm trigger --subsystem-match=nvme-subsystem
----
** *Configuração global na inicialização* — Adicione o seguinte parâmetro do kernel à configuração do seu bootloader:
+
[listing]
----
nvme_core.iopolicy=round-robin
----
** *Não persistente (online, sem interrupção de E/S)* — aplicar imediatamente sem reinicializar:
+
[listing]
----
echo "round-robin" > /sys/class/nvme-subsystem/nvme-subsys0/iopolicy
----
+

NOTE: Essa configuração não persiste após reinicializações.
